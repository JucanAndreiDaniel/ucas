## Findings

### WRONG-1 — f64 `sqrt` double-rounded through `long double`

**Severity:** WRONG
**Source:** `src/eval.c` (`scalar_float`, `O_SQRT`)

Commit `9643c58` moved `O_SQRT` to `sqrtl((long double)a)` followed by
`froundl_once(w, lr)`. For `w == 64` that ends in `(double)v`, a second
rounding. IEEE requires libm's `double sqrt()` to be correctly rounded, so
this can only hurt. Unlike `exp`/`log`/`sin` (whose double libm results are
not guaranteed correctly rounded and genuinely benefit from the long-double
path), sqrt has no table-maker's dilemma for the double result.

Repro (the published hard case for sqrt):

```
show asuint(sqrt(asfloat(u64(0x51fa150473132760))))
# x = 8.1070212242060004e+86
# before: 5256947208003866904   (0x...118, 1 ulp high)
# after:  5256947208003866905   (0x...119, correctly rounded)
```

The machine path disagreed with the ideal plan (which always used `sqrt(a)`),
showing `max 1 ulp` in
`tests/stress/areas/sat/sat_wrap_domain/07_real_vs_f32.out`.

**Fix:** restore `case O_SQRT: r = sqrt(a); break;` so the result is rounded
once by libm for every width. Rounding that correctly-rounded double to f32
or f16 is also correct: double has at least 2p+2 bits for p = 24 (f32) and
p = 11 (f16), so no double-rounding boundary can be crossed. Verified against
an independent oracle (Python `math.sqrt` for f64, numpy float32/float16 for
the narrow widths): all four values in `01_sqrt_f64.ucas` and
`02_sqrt_narrow.ucas` match. The long-double path is kept for EXP/LOG/SIN/COS/
TAN, where it is a genuine fix.

## Checks that passed

- f32/f16 sqrt bit patterns (`02_sqrt_narrow.ucas`) match numpy.
- f64 subnormal sqrt (`01_sqrt_f64.ucas`, third case) matches Python.
- Float edges (`03_float_edges.ucas`): f32/f16 overflow to inf, `-0` bit
  pattern, and `fma64(0.1, 0.2, 0.3)` are unchanged.
- Integer edges (`04_int_edges.ucas`): INT64_MAX+1, abs(INT64_MIN),
  INT64_MIN/-1, signed right shift and an out-of-range u8 shift all keep their
  existing unevaluated/wrapping behaviour.
- Prior wave fixes are preserved: long-double exp/log/sin/cos/tan, bit-level
  `abs`, the INT64_MIN/-1 guard, and the ideal-cast unsigned fix are all still
  in place (a re-run of the published exp worst case returns the correct
  lower double).
